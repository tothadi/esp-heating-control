# CLAUDE.md

Open-source DIN-rail heating controller: two PCBs (KiCad, generated by Python), a 3D-printed enclosure (CadQuery,
generated), and several firmwares. Nothing has been built or tested yet. Read [README.md](README.md) and `docs/` first.

## Working with the user

* The user often writes in Hungarian; reply in the language of the message. Everything in this repo (docs, comments,
  silkscreen, labels) is English.
* When the user asks questions, answer them first. Don't start changes (especially rerouting) until they agree,
  if they say so ("first answer my questions").
* No hacks. Fix the cause, not the symptom: if a part collides, move the parts or the panel instead of cutting a relief
  into the enclosure.
* Commit or push only when asked. Ask before committing.
* Whenever a design change affects outputs, regenerate **all** affected outputs (boards, Gerbers/ZIP, BOM/CPL,
  STL/STEP/DXF, insert drawing, label close-ups, renders). Stale images or drawings count as a bug.
* Verify visually: look at the renders and drawings you produce (text overlaps, collisions, legends). The user checks
  them and spots mistakes such as overlapping text, models rotated against their pads, or labels in the wrong place.
* Check the real part geometry: datasheets (e.g. the OLED active area, not the panel outline), 3D model bodies beyond
  the courtyard (the RJ45 body collided with nearby caps), LCSC stock at JLCPCB.
* Install toolchains (ESP-IDF, esp-matter, Java for Freerouting, Python venvs) only in a sandbox or scratch directory,
  never system-wide.

## Layout

```
hardware/pcb/lower|logic/   KiCad boards (+ terminals.json / front.json); fab/: gerber/, *_gerber.zip, jlcpcb_bom/cpl.csv
hardware/pcb/scripts/       board generators: build_lower.py, build_logic.py, pcbgen.py (shared), export_labels.py, fix/reroute tools
hardware/pcb/components/    footprints.pretty/ (LCSC/EasyEDA, nickname "lcsc"), 3d-models/ (STEP)
hardware/pcb/schematics/    OpenTherm master schematic (SVG generated by script)
hardware/enclosure/         scripts/ (CadQuery/VTK), models/ (STL/STEP/DXF), drawings/ (insert drawing), fonts/
hardware/renders/           all images, flat (no subfolders)
firmware/                   controller (ESPHome), thread-matter (ESP-IDF), h2-rcp, zigbee-coordinator, reference
```

The generator scripts are the source of truth; don't hand-edit `.kicad_pcb` files except for targeted post-fixes. Board
3D model paths must be project-relative (`${KIPRJMOD}/../components/3d-models/…`), never absolute.

## Tooling and gotchas

* **KiCad 10:** use its bundled Python (`/Applications/KiCad/KiCad.app/Contents/Frameworks/Python.framework/Versions/3.9/bin/python3`)
  and `kicad-cli`. pcbnew SWIG crashes when iterating tracks after `Remove` in the same process: split such steps
  into separate processes.
* **Freerouting 2.5 jar needs Java 25** (the native CLI is broken). `ROUTE_GND=1` routes GND too (otherwise GND pads can
  end up fenced in). Min track: 0.15 mm logic, 0.12 mm lower. For leftovers: `fix_unconnected.py <board> 0.05 15`
  with the default clearance (never `CLR=0`). Partial changes: `reroute_partial.py`.
* After moving parts on a routed board, patch the CPL rows too (LCSC footprint origin = centroid). Run DRC; remaining
  items should be cosmetic only.
* **Enclosure:** CadQuery + VTK + matplotlib + shapely in a venv. `build_enclosure.py` reads `terminals.json` and
  `front.json`, so regenerate the boards (and `export_labels.py`) first. `export_insert_drawing.py`,
  `export_label_views.py`, `render_assembly.py` (SVG → PNG via `rsvg-convert -w 1600`), `export_render_parts.py` +
  `render_nice.py` (needs board GLBs from `kicad-cli pcb export glb`). A full enclosure build takes ~3 min.
  Check collisions of cover/base/spacer against the board STEP exports after changes.
* **Printing (JLC3DP):** cover and base SLA CBY resin, labels engraved 0.6 mm (painted by hand, no multicolour);
  DIN latch and OLED spacer MJF PA12-HP; LED rods 8001 clear resin. No JLC3DP material is flame-rated.
* **Firmware:** ESPHome ≥ 2026.9 (Ethernet + Wi-Fi in one build). Validate with `esphome config` and `esphome compile`
  using a temporary `secrets.yaml` (never commit it). ESP-IDF v5.5, esp-matter release/v1.6. All builds compile but
  are untested on hardware; say so.
* **zsh:** an unmatched glob aborts the whole command chain; `rm` targets must be literal paths or `"${VAR:?}"`.
